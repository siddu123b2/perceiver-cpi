I need your help with the 3D part of my final-year project. Before any code, read this and tell
me back in your own words what the system does and what your job is. Do not write code yet.

THE PROJECT
A user types two things into a web page:
  - a compound, as a SMILES string
  - a protein, as an amino-acid sequence
They get back two things:
  1. a binding affinity score - how strongly that compound binds that protein
  2. a 3D picture - where the compound sits inside the protein, and which amino acids it touches

TWO SEPARATE PROGRAMS
This is split into two programs that talk over HTTP. They may run on one machine or two.

  PROGRAM A - the affinity app. Finished. You will not touch it.
    Runs trained Perceiver CPI models and produces the affinity score.
    Serves the web page the user looks at.
    Also has a lookup that finds whether a real solved 3D structure of that pair already exists.

  PROGRAM B - the docking service. This is your job.
    Turns the same SMILES + sequence into a 3D pose, plus the contacting residues.
    It already exists here and partly works. It uses ESMFold, P2Rank, AutoDock Vina and PLIP.

SIX FACTS YOU MUST NOT GET WRONG
These have already cost this project days. Do not argue with them or work around them.

1. The 3D pose is NOT produced by a trained model. AutoDock Vina produces it from physics and a
   scoring function - it tries positions and scores them. There is nothing to learn. Ever.
2. Do not train anything. Not for poses, not for pockets, not for contacts.
3. Someone previously trained a "conditioned 3D" model on ONE complex for 80 epochs as a code
   check. It has no validation data, it is blocked from serving, and it must stay blocked.
   Do not use it, extend it, or train a replacement.
4. The affinity models are already trained and belong to Program A. Never retrain them, never
   write your own scorer.
5. Vina runs on CPU. The pose does not need the GPU.
6. Pockets and contacts need no training either - P2Rank ships pretrained, PLIP is pure geometry.

THE PROBLEM I NEED SOLVED
Right now one job takes about 9 minutes 47 seconds:
  - ESMFold predicting the protein's 3D shape:  5 min 54 s
  - P2Rank finding pockets:                        6 s
  - Ligand preparation and Vina docking:        3 min 47 s
And many jobs fail outright, at three different stages.

MY TWO GOALS
  A. A pose is produced for ANY compound and ANY protein the user types. No silent failures.
  B. Under 4 minutes when the protein already has a known structure.

HOW WE WILL WORK
I will give you ONE task at a time. For each one, tell me:
  1. what you changed, in plain words
  2. the exact command I can run to check it myself
  3. the before/after timing, if the task has one
Never do more than the task I gave you.

Now: tell me back what this system does and what your role is. Then wait.

Run these yourself on the docking laptop, in the project folder:

    .venv\Scripts\python.exe -m uvicorn backend.app:app --host 0.0.0.0 --port 8010

  When Windows Firewall asks, choose "Allow on private networks".

    ipconfig          -> note the IPv4 Address, for example 192.168.1.42

    $env:PERCEIVER_DOCKING_URL = "http://192.168.1.42:8010"

Check the link:

    curl http://127.0.0.1:8000/api/docking/status      -> should say "connected": true

    curl http://192.168.1.42:8010/api/complexes
If THAT also fails, the problem is the firewall or the network, not the code.
